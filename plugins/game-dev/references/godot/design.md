# Godot 详细设计模板

---

## 对每个新建的 scene

```markdown
### {scene_name}.tscn（新建）

**定位：** 这个 scene 在游戏中的角色——做什么，管什么。

**节点树：**

RootNode (NodeType)
├── Child1 (NodeType)              # 用途
│   └── Grandchild (NodeType)      # 用途
└── Child2 (NodeType)              # 用途
    └── (挂载点，子 scene 结构见本节第 N 章)

**关键属性：**

- 节点路径: property = value（非默认值）

**主要逻辑：**

从架构第 2 章（领域模型实现）下发——FSM 流转规则、输入缓冲机制、能量管理模式、关键时序等。用行为语言 + 关键数据结构描述。

**内部信号连接：**

NodeA.signal → NodeB.method()

**外部接口调用：**

从架构第 5 章取——本 scene 调用的外部接口，含完整签名和调用时机：

| 调用接口 | 完整签名 | 调用时机 |
|---------|---------|---------|
| External.method | method(param: Type) -> ReturnType | 何时调用 |

**对外暴露接口：**

从架构第 5 章取——本 scene 暴露给外部的接口，含完整签名：

| 接口 | 完整签名 | 调用方 | 触发时机 |
|------|---------|--------|---------|

**参与的交互流程：**

从架构第 3.2 章取——本 scene 参与的关键信号链段落：

输入 → 本 scene 的处理 → 输出到哪个 scene

**依赖的初始化条件：**

从架构第 7 章取：

- 本 scene `_ready()` 之前必须已完成：{autoload / 父 scene / 其他}
- 本 scene `_ready()` 中需要做的初始化

**显示推导：**

用户在这个 scene 中看到什么——画面描述、位置、布局。

**资产: {名称}**
- 用途: {一句话}
- 类型: {精灵/纹理/UI素材/材质}
- 尺寸: {W×H}
- 视觉要求: {颜色、材质、风格}
```

## 对每个修改的 scene

从架构全景图和场景清单得出变更范围——实际有什么写什么，不预设固定字段。

```markdown
### {scene_name}.tscn（修改）

**为什么改：** {从架构全景图——这个 scene 在树上的角色变化}

**改什么：** {从架构得出，实际变更内容}

**挂载scene变化: ** {如有如实写，新增或者删除}

**外部接口变化：** {如有——新增/修改/删除的调用接口}

**自身初始化顺序变化：** {如有——本 scene 的 `_ready()` 变更}
```

---

## 内容规则

**必须遵守：**
- 新建 scene 的节点树完整展开到底
- 外部接口和交互流程从 architecture 对应章节获取，不自己编造
- 主要逻辑从 domain-design + architecture 第 2 章下发
- 按 architecture 场景清单逐行编写，不在清单里的 scene 不写

**禁止内容：**
- GDScript 代码
- 跨 scene 接口的完整签名自己发明（必须从 architecture 取）
- 文件路径（scene 文件名除外）
